# Producción

URL: <https://securetex.dayle.dev>. Oracle ARM64, `~/securetex`, sin puertos publicados; Cloudflare Tunnel propio. El resto de servicios del servidor no forma parte del despliegue.

El SHA del commit identifica las cuatro imágenes (API, web, compilador y controlador) y la revisión que devuelve la web.

- **Disparador:** PR a `develop`; después PR de `develop` a `main`. El workflow «Validación y producción» comprueba lint, tipos, unitarias/cobertura, casos de abuso, navegadores, accesibilidad, contrato, documentación, dependencias y secretos. Solo un `push` a `main` que pase publica las cuatro imágenes ARM64 en GHCR, etiquetadas con su SHA, y despliega esa versión.
- **Acceso:** environment `production`; `DEPLOY_SSH_KEY` y `DEPLOY_KNOWN_HOSTS` en Secrets, `DEPLOY_HOST` en Variables. Clave SSH exclusiva con comando forzado `infra/ssh-deploy.sh` y `restrict`; sin shell ni reenvíos. GHCR usa el `GITHUB_TOKEN` de corta duración, guardado en RAM durante el despliegue.
- **Cambio de versión:** copia de PostgreSQL, migraciones revisadas, candidata aislada, compilación real efímera, redirecciones OAuth, demo y permisos, cambio de gateway, comprobación interna y por HTTPS público de `/health` (incluida la base), landing y SHA. La sonda pública sale desde Oracle; la llamada directa desde el runner de GitHub recibió un 403. Si falla, restaura la anterior; los cambios colaborativos se vacían antes de detener cada API. Conserva las últimas tres versiones y sus copias; limpia únicamente recursos de SecureTex.
- **Volver atrás:** por SSH administrativo, `cd ~/securetex && ls -t releases` y `./deploy.sh <SHA-anterior> --local-images`. Las imágenes de las tres últimas versiones están en el servidor. No restaura la base ni pierde las ediciones posteriores.
- **Migraciones nuevas:** nunca modificar las existentes. Antes de admitir otra, revisar que la aplicación anterior siga funcionando con el nuevo esquema y actualizar `infra/migrations-approved.json` en el repo **y en el servidor**. El despliegue bloquea SQL sin revisar antes de ejecutarlo; una migración destructiva requiere un plan de mantenimiento aparte. No se hace un `db push` ni se elimina la base para revertir.
- **Si falla:** GitHub → Actions → ejecución roja → primer paso fallido. Mantener activadas las notificaciones de Actions por correo. En Oracle: `cat ~/securetex/current`, `docker logs --tail 100 securetex-gateway` y `docker logs --tail 100 securetex-api-<SHA>`. Nunca mostrar el `.env` ni `docker inspect` completo con sus variables. La infraestructura del host se actualiza por SSH administrativo tras revisión; los cambios de la aplicación se despliegan solos.

La demo conserva sus nueve identidades sintéticas, sin administradores ni contraseñas, y se reinicia en `America/Guayaquil`. Las cuentas reales requieren [configurar y validar OAuth y correo](OAUTH.md). No hay Mailpit ni puertos publicados de SMTP en Oracle; Resend se usa por TLS saliente. El remitente es `no-reply@securetex.dayle.dev`.

El controlador crea un gVisor sin red por trabajo y lo destruye antes de entregar el PDF. Su clave propia solo admite `sandbox-job SHA UUID` desde la red de SecureTex. La primera entrega actualiza también el compilador anterior antes de activar cuentas: una reversión conserva el aislamiento. `controller-current` permite ejecutar un trabajador antiguo con el último controlador validado. La provisión inicial es `python3 infra/provision-sandbox.py`; no repetirla si ya existe la clave.

Los cargadores `configure-oidc.py` y `configure-resend.py` piden los secretos sin mostrarlos; `check-mail.py` permite solicitar una prueba a tu correo sin guardarlo. Editar el `.env` no modifica los contenedores existentes: los valores se aplican al crear una entrega con SHA nuevo.

`infra/migrations-approved.json` es un manifiesto público sin secretos: debe ser legible por el verificador del contenedor (644), montado de solo lectura. El `.env` conserva 600. Tras cambiar cabeceras de seguridad de recursos con URL estable, comprobar también el worker PDF desde un navegador: Cloudflare puede conservar la respuesta anterior. Renovar únicamente las URL afectadas de `securetex.dayle.dev`, sin purgar la zona completa.
